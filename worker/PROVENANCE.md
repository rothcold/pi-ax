# Worker image provenance

- AX: https://github.com/google/ax at `ac2332829f22360ff97b0ba34d94dd0dd782f17e`, Apache-2.0. Dockerfile downloads the official API tarball with SHA-256 `9b98d0c22d3962b2a1f0f6ab3135e4513d5dc63c4dfd3cc26d562f94ea7224a9`, builds the **unmodified** `cmd/ax-task-runner`, and includes its upstream LICENSE in the final image. Existing vendored `../proto/LICENSE` also contains the AX Apache-2.0 license. No upstream source is edited.
- AX go.mod pins env `4468a200b1702503ef9b84cf078e58ac517ad877` and Substrate `944abe3278b895ccbf5d45555a49dd0f2f6ceae7` (both Apache-2.0); its go.sum supplies dependency integrity. Go toolchain image: `golang:1.27.1-bookworm`. The image includes `go version -m` binary build metadata plus dependency LICENSE/NOTICE/COPYING files collected from the Go module cache.
- Node image: `node:24.13.0-bookworm-slim`. Git, SQLite CLI, Bash, ca-certificates and procps come from Debian repositories; package revisions and base image digests must be recorded in runtime acceptance (tags/apt packages are not content-pinned).
- Pi: npm `@earendil-works/pi-coding-agent@latest`, MIT, resolved afresh by `scripts/build-image.mjs` for every supported build. No worker project lockfile is shipped. The exact resolved version is verified after installation, saved in `/opt/pi/pi-version`, printed in the build log and recorded as image label `org.pi-ax.pi.version`. Package licenses and Pi's upstream-published shrinkwrap remain inside node_modules; no upstream dependency override is applied. Historical 0.99.2 image/guest evidence is in `docs/v1-validation.md`, not a current version requirement. No host Pi/global configuration or auth is copied.
- Root `npm-shrinkwrap.json` remains the exact build/test tooling lock, including Pi 0.99.2 for local regression tests. It does not select the final worker Pi runtime. Rebuild to obtain newer npm latest releases; existing images/tasks do not self-update. Future release compatibility requires renewed validation.
- `worker/supervise.c` is original Linux child-subreaper code, compiled with Debian `cc` in the existing Go/bookworm build stage and installed at `/opt/pi-ax/dist/worker/supervise`. It only signals/reaps its own child tree, including ordinary detached Pi bash jobs; it is not an upstream patch or hostile-process isolation guarantee.
- Wrapper and workspace code are original project implementation. No Antigravity bootstrap, MCP configuration, extensions, skills, credentials, or host environment are baked into the image.

Building this image is not AX/gVisor acceptance. Deployment must use the produced immutable image digest and verify that AX actually selects it rather than a fallback template. AX authentication, network isolation and resource enforcement deficiencies are deferred upstream limitations, not changes implemented by this image.
